# Верификатор программ

`Verifier` статически проверяет готовую `Program` перед запуском: не выполняя код, ищет ошибки в инструкциях, в потоке управления и в типах регистров. Собирает **все** проблемы, а не только первую. Проблемы бывают двух уровней: `Error` и `Warning`.

- `verifier.h` — `Verifier`, `VerifyError`, `Severity`, `RegType`, `OpInfo` и связанные перечисления.
- `verifier.cpp` — таблица инструкций `op_table` и сами проверки.

## Использование

```cpp
Program program = load_program(path);
Verifier verifier(program);

bool has_errors = false;
for (const VerifyError &e : verifier.verify()) {
    bool is_error = e.severity == Severity::Error;
    std::cerr << (is_error ? "error" : "warning")
              << " at pc " << e.pc << ": " << e.message << "\n";
    has_errors = has_errors || is_error;
}
// запускаем программу, только если has_errors == false
```

- Верификатор хранит ссылку на `Program`, программа должна жить дольше него.
- `verify()` можно вызывать повторно: список проблем очищается.
- `pc` — индекс инструкции; для проблем всей программы — 0 (или индекс конкретной инструкции, если проблема на ней).

## Описание инструкций

Каждая инструкция описана в `op_table` записью `OpInfo`:

| Поле | Смысл |
|---|---|
| `format` | `Abc` (три регистра) или `Ad` (регистр и число `d`) |
| `use_a/b/c` | какие регистровые поля используются |
| `d` | проверка `d`: `None`, `Constant` (индекс константы) или `Jump` (адрес перехода) |
| `flow` | передача управления: `Normal` (`pc+1`), `Jump` (`d`), `Conditional` (`d` и `pc+1`), `Call` (`d` и `pc+1`), `Return`, `Stop` |
| `regs` | требуемые типы регистров `a`, `b`, `c`: `Int`, `Float` или `Any` |

Новую инструкцию достаточно добавить строкой в `op_table`. Опкод вне таблицы считается неизвестным.

## Что проверяется

**Каждая инструкция отдельно**

- опкод известен;
- неиспользуемые поля равны нулю;
- индекс константы (`LK`) существует, цель перехода лежит внутри кода;
- номера регистров не превышают `MAX_REGISTER` (255).

**Программа целиком**

- программа не пуста;
- по графу потока управления от инструкции 0 находятся:
  - возможный выход за конец программы;
  - недостижимые инструкции;
  - отсутствие пути к завершению (завершением считаются `STP` и `RET`);
  - ветвления, после которых можно уйти в бесконечный цикл (предупреждение на самом ветвлении).

**Типы регистров**

Анализ потока данных: для каждой инструкции хранится состояние регистров перед ней. Тип регистра: `None` (не записан), `Int`, `Float` или `Any` (неизвестно или разный на разных путях).

1. Состояние распространяется по рёбрам графа; при слиянии путей разные типы объединяются в `Any`. Рабочий список повторяется, пока состояния не перестанут меняться.
2. Эффект инструкции (`write_result`): арифметика и сравнения дают `Int`, вещественные операции `Float`, `MV` копирует тип, `LK` берёт тип константы.
3. `CALL`: тело функции начинается с `Any` во всех регистрах; после возврата `a` становится `Any`, а регистры выше `a` — `None`.
4. После стабилизации каждая достижимая инструкция проверяется: читаемый регистр со значением `None` — ошибка, тип не совпал с требуемым — ошибка. `Any` не проверяется.

## Сообщения

| Сообщение | Уровень | Где |
|---|---|---|
| `unknown opcode` | Error | инструкция |
| `field 'a' must be 0` (также `'b'`, `'c'`) | Error | инструкция |
| `there is no constant with that number` | Error | инструкция |
| `jump target out of range` | Error | инструкция |
| `register 'a' must be in range [0; 255]` (также `'b'`, `'c'`) | Error | инструкция |
| `program is empty` | Error | 0 |
| `execution can go past the end` | Error | последняя инструкция |
| `program has no path to termination` | Error | 0 |
| `instruction is unreachable` | Warning | инструкция |
| `there could be an infinite loop` | Warning | ветвление |
| `register 'a' not initialized` (также `'b'`, `'c'`) | Error | инструкция |
| `types of register 'a' not matched` (также `'b'`, `'c'`) | Error | инструкция |

Порядок в результате: проблемы отдельных инструкций, затем граф (выход за конец, недостижимость, путь к завершению, бесконечные циклы), затем типы.

## Ограничения

- Анализ структурный: значения регистров не вычисляются, поэтому цикл с условием выхода, которое на деле никогда не выполнится, цикл не считается бесконечным.
- Если на разных путях регистр получает разные типы (или записан не на всех путях), он становится `Any`, и такая проблема не обнаруживается.
- `CALL` моделируется приближённо: возврат из функции считается всегда успешным, а глубина вызовов не анализируется.
